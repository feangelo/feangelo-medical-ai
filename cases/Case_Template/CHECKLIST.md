# Case Checklist

## Governance

- [ ] Case uses a non-identifying name.
- [ ] `case.yaml` declares `synthetic`, `open-dataset`, or `public`.
- [ ] Provenance, version, license, and access date are recorded.
- [ ] Redistribution permission has been reviewed.
- [ ] No private clinical data or identifiers are present.
- [ ] Headers, pixels, overlays, filenames, and metadata were inspected.

## Reproducibility

- [ ] Objective and acceptance criteria are defined.
- [ ] Software and versions are recorded.
- [ ] Parameters and configuration are versioned.
- [ ] Random seeds are recorded when relevant.
- [ ] Inputs are referenced by version and checksum when possible.
- [ ] Processing can be repeated from documented instructions.

## Segmentation and quantitative quality

- [ ] Orientation, spacing, scale, and units were verified.
- [ ] Segmentation underwent documented anatomical and technical review.
- [ ] Smoothing and manual corrections are documented.
- [ ] Measurements include methods, units, and limitations.
- [ ] Metrics identify their reference standard.
- [ ] Mesh exports passed scale and integrity checks.

## Publication

- [ ] Claims match the available evidence.
- [ ] Limitations and non-clinical status are visible.
- [ ] Screenshots and derived assets passed privacy review.
- [ ] Third-party attribution and citations are complete.
- [ ] Repository owner approved publication.
- [ ] Case status is updated only after evidence review.
